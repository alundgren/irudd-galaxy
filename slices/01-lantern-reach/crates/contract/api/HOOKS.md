# The Luau hook API

GENERATED by `cargo xtask contract` from `crates/contract/src/api.rs`. Do not edit.

A pack's scripts reach the world only through `ctx`, built from the manifest's
`uses` list: undeclared namespaces and functions are absent at runtime and are
type errors in `galaxy pack check`. Every write takes a cause from
`ctx:cause { summary = ..., cites = { fact IDs } }` and becomes a command in the
handler's buffer; if the handler errors or runs over budget, nothing applies.
Types are in [`galaxy.d.luau`](galaxy.d.luau).

## Script shape

```luau
--!strict
local G = require("@galaxy")
return G.script {
	id = "kettle_growth",
	on = {
		sell = function(ev: G.SellEvent, ctx: G.Ctx) end,
	},
	after = {
		regulars = G.after({ dockings = 3, station = "station.kettle_dock" }, function(ctx, fire) end),
	},
}
```

Always on `ctx`: `ctx.pack`, `ctx.script`, `ctx:cause`, `ctx.rng` (seeded per script)
and `ctx.store` (the script's declared stores).

## Functions

### `ctx.canon`

- `ctx.canon:status(id: string) -> string?` (`canon.read`): Read a canon node's current status.
- `ctx.canon:open(id: string, why: Cause) -> ()` (`canon.write`): Open a manifest-declared node when its authored prerequisites hold. Reversible.

### `ctx.kit`

- `ctx.kit:station(station: Station, recipe: string, dockmaster: Npc, market: { [WareId]: MarketLine }, why: Cause) -> ()` (`kit.write`): Found a namespaced station from a JSON recipe validated against the shared art bible. Needs `npcs.write` and `market.lines` too. A later revision of the pack that founded it reopens its rolled-back scaffold in place.
- `ctx.kit:buoy(id: string, buoy: SurveyBuoy, why: Cause) -> ()` (`kit.write`): Place or replace a survey buoy, unread and unclaimed. Space in reach reads its log and records survey_buoy_read. A reward is paid natively on a reply to its person: credits need `beats.write`, standing (a deed) needs `standing.write`.
- `ctx.kit:overlay(id: string, overlay: MapOverlay?, why: Cause) -> ()` (`kit.write`): Put or remove a namespaced map border or bearing.

### `ctx`

- `ctx:cause(spec: CauseSpec) -> Cause` (always): The cause for this handler's writes. `cites` are history fact IDs; they must exist. One per call: everything a handler writes applies together or not at all.

### `ctx.rng`

- `ctx.rng:int(lo: number, hi: number) -> number` (always): A whole number in `lo..=hi` from the script's seeded stream.
- `ctx.rng:float() -> number` (always): A number in `0..1` from the script's seeded stream.

### `ctx.store`

- `ctx.store:get(store: string, key: string) -> ScriptValue?` (always): A value from one of the script's declared stores.
- `ctx.store:set(store: string, key: string, value: ScriptValue?, why: Cause) -> ()` (always): Sets (or clears, with nil) a declared key. The type must match the manifest.

### `ctx.counters`

- `ctx.counters:get(kind: CounterKind, scope: CounterScopeArg?) -> number` (`counters.read`): An activity counter for the player, or a station or region.

### `ctx.history`

- `ctx.history:count(q: HistoryQuery) -> number` (`history.read`): How many facts match.
- `ctx.history:sum(q: HistoryQuery) -> number` (`history.read`): The sum of `amount` over matching facts.
- `ctx.history:find(q: HistoryQuery) -> { Fact }` (`history.read`): Matching facts, oldest first. At most `q.limit`, and never more than 50.
- `ctx.history:last(q: HistoryQuery) -> Fact?` (`history.read`): The most recent matching fact.
- `ctx.history:fact(id: FactId) -> Fact?` (`history.read`): One fact by ID.
- `ctx.history:record(fact: FactDraft, why: Cause) -> ()` (`history.write`): Records a fact when the batch commits. Its kind carries the pack prefix: `gm.stage_built`.

### `ctx.stations`

- `ctx.stations:get(id: StationId) -> Station?` (`stations.read`): A station record.
- `ctx.stations:list() -> { StationId }` (`stations.read`): Every station ID, sorted.
- `ctx.stations:stage(id: StationId) -> number` (`stations.read`): A station's build stage.
- `ctx.stations:parts(id: StationId) -> { PartId }` (`stations.read`): A station's attached kit parts, sorted.
- `ctx.stations:set_stage(id: StationId, stage: number, why: Cause) -> ()` (`stations.write`): Sets a station's build stage.
- `ctx.stations:attach(id: StationId, part: PartId, why: Cause) -> ()` (`stations.write`): Attaches a kit part to a station.
- `ctx.stations:detach(id: StationId, part: PartId, why: Cause) -> ()` (`stations.write`): Detaches a kit part.
- `ctx.stations:set_owner(id: StationId, owner: FactionId?, why: Cause) -> ()` (`stations.write`): Sets (or clears) a station's owner.

### `ctx.parts`

- `ctx.parts:get(id: StationPartId) -> StationPart?` (`stations.read`): A station part: a room with a module, a keeper and a sign.
- `ctx.parts:list(station: StationId) -> { StationPartId }` (`stations.read`): A station's part IDs, sorted.
- `ctx.parts:put(part: StationPart, why: Cause) -> boolean` (`stations.write`): Adds or changes a station part at a calm moment, and its keeper says its `line`          citing `why` (needs `talk.write` too). Only while the player is docked:          otherwise nothing is written and it returns false. Checked: the anchor is free          on the station's recipe, the module is within the art bible's budget, the keeper          is at the station. `state = "closed"` puts a scaffold and a closed sign up.
- `ctx.parts:remove(id: StationPartId, why: Cause) -> boolean` (`stations.write`): Takes a station part away at a calm moment; its keeper says its          `rollback_line` citing `why` (needs `talk.write` too). False while the player          isn't docked.

### `ctx.happenings`

- `ctx.happenings:get(id: HappeningId) -> Happening?` (`happenings.read`): A happening, with where it is in its run (`run.status`: upcoming, active, ended).
- `ctx.happenings:list(station: StationId) -> { HappeningId }` (`happenings.read`): A station's happenings, upcoming, running and over, sorted by ID.
- `ctx.happenings:active(station: StationId) -> HappeningId?` (`happenings.read`): The happening running at a station now, if any (at most one at a time).
- `ctx.happenings:put(happening: Happening, why: Cause) -> ()` (`happenings.write`): Writes a new or still-upcoming happening. It starts once every `cause.facts` entry          exists (a fact ID that must exist now, or a pattern: `kind` plus subjects or          `amount`) and the player is docked at its station with nothing else running          there; its speaker says `line.text` and it runs for `lasts.dockings` counted          dockings. Checked: the station exists, the speaker is there, the line is one          short first-person line, `lasts.dockings` is 1 to 12. Leave `run` and `by` out.          Needs `talk.write` too: the speaker talks.
- `ctx.happenings:remove(id: HappeningId, why: Cause) -> ()` (`happenings.write`): Takes away a happening that hasn't started. One that is running or over stays.

- `ctx.factions:list() -> { FactionId }` (`factions.read`): Every faction ID, sorted.
- `ctx.factions:standing(id: FactionId) -> number` (`factions.read`): The player's standing with a faction.
- `ctx.factions:adjust_standing(id: FactionId, delta: number, why: Cause) -> ()` (`factions.write`): Raises or lowers the player's standing.

### `ctx.npcs`

- `ctx.npcs:list() -> { NpcId }` (`npcs.read`): Every NPC ID, sorted.
- `ctx.npcs:at(station: StationId) -> { Npc }` (`npcs.read`): People found at a station.
- `ctx.npcs:put(npc: Npc, why: Cause) -> ()` (`npcs.write`): Creates or replaces a person. New IDs are namespaced by the pack.
- `ctx.npcs:move(id: NpcId, station: StationId?, why: Cause) -> ()` (`npcs.write`): Moves a person to a station (or nowhere).

- `ctx.rumors:put(rumor: Rumor, why: Cause) -> ()` (`rumors.write`): Plants or replaces a rumor.
- `ctx.rumors:set_truth(id: RumorId, is_true: boolean, why: Cause) -> ()` (`rumors.write`): Sets a rumor's truth value.
- `ctx.rumors:spread(id: RumorId, station: StationId, why: Cause) -> ()` (`rumors.write`): A rumor starts being told at a station.

### `ctx.territory`

- `ctx.territory:owner(region: RegionId) -> FactionId?` (`territory.read`): Who holds a region.
- `ctx.territory:station_owner(station: StationId) -> FactionId?` (`territory.read`): Who holds a station.
- `ctx.territory:set_owner(region: RegionId, owner: FactionId?, why: Cause) -> ()` (`territory.write`): Moves a region to a faction (or makes it unclaimed).
- `ctx.territory:set_station_owner(station: StationId, owner: FactionId?, why: Cause) -> ()` (`territory.write`): A station changes hands.

### `ctx.market`

- `ctx.market:line(station: StationId, ware: WareId) -> MarketLine?` (`market.read`): One ware's stock line at a market.
- `ctx.market:lines(station: StationId) -> { [WareId]: MarketLine }` (`market.read`): Every stock line at a market.
- `ctx.market:add_line(station: StationId, ware: WareId, line: MarketLine, why: Cause) -> ()` (`market.lines`): Adds a ware the market didn't trade yet. Prices must sit inside the line's band.
- `ctx.market:remove_line(station: StationId, ware: WareId, why: Cause) -> ()` (`market.lines`): Removes a ware's stock line.
- `ctx.market:scale_producers(station: StationId, ware: WareId, factor: number, why: Cause) -> ()` (`market.levers`): Multiplies a line's production (1.5 for +50%). Prices follow from supply.
- `ctx.market:scale_consumers(station: StationId, ware: WareId, factor: number, why: Cause) -> ()` (`market.levers`): Multiplies a line's consumption (2 for a shortage's drink).
- `ctx.market:add_producers(station: StationId, ware: WareId, per_pulse: number, why: Cause) -> ()` (`market.levers`): Adds (or with a negative number removes) producer units per pulse.
- `ctx.market:add_consumers(station: StationId, ware: WareId, per_pulse: number, why: Cause) -> ()` (`market.levers`): Adds (or removes) consumer units per pulse.
- `ctx.market:set_stock(station: StationId, ware: WareId, stock: number, why: Cause) -> ()` (`market.levers`): Sets a line's stock outright (a delivery, a gift).
- `ctx.market:pulses(station: StationId) -> number` (`market.read`): Activity pulses a station has had so far (fractional). Pace by these, never by time.
- `ctx.market:levers(levers: { Lever }, why: Cause) -> ()` (`market.levers`): Several levers in order, each seeing the ones before it. Use this to compose levers on one line in one call. `add_line` and `remove_line` levers need `market.lines` too.

### `ctx.orders`

- `ctx.orders:get(ship: ShipId) -> OrderQueue?` (`orders.read`): A craft's order queue.
- `ctx.orders:can_order(ship: ShipId) -> boolean` (`orders.read`): Whether scripts may give this ship orders (scripted craft and the player's tenders; never the player ship or a berthed hull).
- `ctx.orders:give(ship: ShipId, orders: { Order }, why: Cause) -> ()` (`orders.write`): Replaces a craft's orders with these (the same verbs the player uses).
- `ctx.orders:append(ship: ShipId, order: Order, why: Cause) -> ()` (`orders.write`): Adds one order to the end of a craft's queue.
- `ctx.orders:clear(ship: ShipId, why: Cause) -> ()` (`orders.write`): Clears a craft's orders.

### `ctx.beats`

- `ctx.beats:state(id: BeatId) -> BeatState?` (`beats.read`): A started beat's state (dormant beats have none).
- `ctx.beats:is_done(id: BeatId) -> boolean` (`beats.read`): Whether a beat has completed.
- `ctx.beats:is_active(id: BeatId) -> boolean` (`beats.read`): Whether a beat has started and not completed.
- `ctx.beats:active() -> { BeatId }` (`beats.read`): Active beats, newest first.
- `ctx.beats:goal() -> GoalLine?` (`beats.read`): The one goal line the HUD shows: the newest active beat's.
- `ctx.beats:goals() -> { GoalLine }` (`beats.read`): Every active beat's goal line, newest first (the dockmaster's list).
- `ctx.beats:act() -> number` (`beats.read`): The act the journey is in (the highest act of any started beat).
- `ctx.beats:pilot() -> PilotView` (`beats.read`): The player as a beat sees them: ship, hull, where they're docked, region, position, their own cargo, consignments carried for others (by ledger), hold room and credits (in credits).
- `ctx.beats:service(id: UpgradeId | ShipId) -> ServiceView?` (`beats.read`): An upgrade or tender a hullwright or dockmaster offers (`upgrades.toml`): its name, its literal effect text, its cost in credits, who sells it and where, and whether the player has it (`owned`: fitted, or the tender built). `nil` for an unknown ID. For the lines that offer a gift and say it's fitted.
- `ctx.beats:distance(to: StationId | Spot) -> number?` (`beats.read`): How far the player's ship is from a station or a spot, in u. `nil` without a ship, or when the target is in another region (a spot without `region` is in the ship's).
- `ctx.beats:field(id: FieldId) -> FieldView?` (`beats.read`): A rock field's depletion: how many rocks, units left and when full, and `left` (remaining / full, 0 to 1). `nil` for an unknown field.
- `ctx.beats:rock(id: RockId) -> RockView?` (`beats.read`): One rock: its field, position, units left and when generated, and `left` (0 to 1). `nil` for an unknown rock.
- `ctx.beats:deliver(spec: DeliverSpec, why: Cause) -> ()` (`beats.write`): A goal handover: takes cargo from the docked player ship and writes `deliver` (to a ledger, if given). Fails unless docked there with the cargo.
- `ctx.beats:expect_docked(station: StationId, why: Cause) -> ()` (`beats.write`): Changes nothing: the call's writes apply only if the player is still docked at `station` when they do (an undock earlier in the tick makes the call contention). Fails unless docked there now. For changes that wait for a calm moment.
- `ctx.beats:load(spec: LoadSpec, why: Cause) -> ()` (`beats.write`): Loads goal cargo into the player ship as the pilot's own: at a dock, or with `found = true` something found in space, wherever the ship is. Fails without the hold room. Someone else's goods go aboard with `consign`.
- `ctx.beats:consign(spec: ConsignSpec, why: Cause) -> ()` (`beats.write`): Loads someone else's goods into the docked player ship under a ledger: they fill hold space but stay the owner's (no market buys them) until `deliver_consignment` hands them to the person they're for. Fails without the hold room, or if that ledger's consignment is already aboard. Cite the player's `reply` accepting it.
- `ctx.beats:deliver_consignment(ledger: LedgerId, why: Cause) -> ()` (`beats.write`): Hands the whole consignment under `ledger` to the person it's for and writes `deliver` (ware, quantity, the ledger). Fails unless the player is docked where that person is with the consignment aboard.
- `ctx.beats:pay(credits: number, why: Cause) -> ()` (`beats.write`): Pays the player credits (credits, not centicredits; more than 0): a fee for a hand-in or an offer the player accepted. The call's cause must cite the player's `reply` agreeing to it, or none of its writes apply (`unconfirmed_change`). Never takes credits.

- `ctx.space:craft(id: ShipId) -> CraftView?` (`space.read`): A non-player craft as scripts see it: hull, owner, where it is docked, region, position and cargo. `nil` if there's no such ship.
- `ctx.space:put_craft(spec: CraftSpec, why: Cause) -> ()` (`space.write`): Launches a scripted craft owned by a named person (a teacher's tender, a prospector's skiff), berthed at a station with its cargo. New IDs are namespaced by the pack.
- `ctx.space:put_field(spec: FieldSpec, why: Cause) -> ()` (`space.write`): Lays out a new rock field with its rocks at authored positions (a rumored vein found). New IDs are namespaced by the pack.
- `ctx.space:set_regrow(field: FieldId, per_pulse: number, why: Cause) -> ()` (`space.write`): Sets a field's regrowth per region pulse (letting a field rest). A rollback restores it.

- `ctx.mechanics:teach(spec: TeachSpec, why: Cause) -> ()` (`mechanics.write`): A new verb with a teacher: sets the `mech.*` flag, binds its slots, and records `<pack>.mechanic_taught` naming the teacher.

- `ctx.standing:deed(spec: DeedSpec, why: Cause) -> ()` (`standing.write`): Records a deed: moves standing (clamped, scaled by traits for `tags`) and writes `standing_changed` and, if the tier moves, `regard_changed`.

### `ctx.traits`

- `ctx.traits:earned() -> { TraitId }` (`traits.read`): The pilot's traits, sorted.

### `ctx.pacing`

- `ctx.pacing:get(id: TunableId) -> TunableValue?` (`pacing.read`): A tunable's current value: a number, a string or a list of strings.

- `ctx.pacing:set(id: TunableId, value: TunableValue, why: Cause) -> ()` (`pacing.write`): Varies a tunable. Set it while the beat that reads it is dormant; a rollback restores the authored value.

### `ctx.talk`

- `ctx.talk:selected(request: FactId, line: string) -> DockTalkCandidate?` (`talk.pick`): Reads an offered candidate only if this pack revision, docking and speaker still match and its fact has not been said. Otherwise nil. Recheck docking when saying it.

### `ctx.map`

### `ctx.chronicle`

- `ctx.chronicle:write(line: LineSpec, why: Cause) -> ()` (`chronicle.write`): Writes a chronicle entry. Needs a `speaker` or `place` and `cites`.

## Beats (`beats.write`)

A script registers beats with `G.beat` in `G.script { beats = { ... } }`. The script
host checks each beat every tick: a dormant beat starts when `requires` holds
(`beat_started`), each step finishes when its `done` holds (the next step writes
`quest_step`, with `quest` = the beat ID), and the beat completes when every step is
done and its `done` holds (`beat_completed`, then `rewards`). Beat state lives in the
world by stable ID, so beats survive save, load and hot reload.

```luau
G.beat {
	id = "beat.b02_mine_by_hand",
	act = 1,
	giver = "npc.ilse_marrow",
	goal = "Hold Space beside an ice rock until your hold is full.",
	requires = G.done("beat.b01_undock"),
	done = G.cargo("ware.ice", G.tunable("b02.ice")),
	rewards = { credits = 0 },
	on_complete = function(ctx, beat) end, -- optional; writes with beat.why are atomic with it
}
```

- Requirements never name a time. Build them with `G.all`, `G.any`, `G.never`,
  `G.done`, `G.started`, `G.active`, `G.at_step`, `G.counter`, `G.fact`, `G.sum`,
  `G.flag`, `G.trait`, `G.fitted`, `G.hull`, `G.owns`, `G.credits`, `G.cargo`,
  `G.hold_free`, `G.docked_at`, `G.docked`, `G.in_region`, `G.near`, `G.regard`,
  `G.tunable_is`, and `G.test(function(ctx) return ... end)` for anything else (read
  only). A list of requirements means all of them. `G.fact`/`G.sum` take
  `{ since = "start" }` or `"step"` to count only facts after the beat or step began.
- Numbers can be `G.tunable("id")`: pacing thresholds live in `pacing.toml`.
- `kind = "situation"` marks a state-driven beat (shortage, dispute, rumor); it runs
  the same way.
- Callbacks `on_start`, `on_step` and `on_complete` get `(ctx, beat)`. To say a line
  that cites the beat's fact, handle `on.beat_started` / `on.quest_step` /
  `on.beat_completed` instead: their `ev.fact` exists.
- A transition and its callback's writes are one batch, checked like a handler's
  against the world the kernel will apply it to. If it would be rejected, none of it
  applies and later beats don't see it: a successor unlocks only on a completion that
  commits. A transition that loses to contention (say the player undocked earlier in
  the tick) doesn't count as an abort; the beat is checked again next tick.
- `ctx.beats:goal()` is the HUD's one goal line (the newest active beat's).

## What each write needs

The hooks above are gated one by one, but a pack also writes through routes that
aren't one hook: a beat's transition and rewards, a trigger's bookkeeping, its
`data` files, a buoy reward the pilot claims later. Every batch a pack causes is
checked against this table before it is submitted (`galaxy_contract::needs`):
handler and trigger calls, beat transitions with their rewards and callbacks, and
data installs. A command whose capability isn't in `uses` rejects the whole batch
as a fault, naming the command and what it lacks. `galaxy pack check` checks the
same table against what the pack's data would install and its beats' rewards
would write (`npcs.toml` needs `npcs.write`). `a` or `b` means either will do;
"never" means only the engine, native systems, the player's verbs, the host or
a rollback writes it; "beat runtime only" means only a core-layer pack's
`G.beat` transition writes it, never a hook, a callback or data, and never a
game-master layer (recorded in the world's pack state, so a reload keeps it).

Provenance: a pack records facts only in its own namespace, `<pack-id>.*` (the
whole ID). Engine events (docking, trades, mining ...) never come from a pack,
and the journey's beat events only from the beat runtime. A fact or event that
reports a checked change comes right after that change in the same batch
(`<pack-id>.canon_opened` after `ctx.canon:open`'s `set_canon_status`), so no
beat precondition can be met by a forged fact.

## Not available to scripts

No clock, timer or wall time (`os`, `wait`, `delay`, `tick`); no `math.random`
(use `ctx.rng`); no `loadstring`, `getfenv`, `setfenv`; `require` only sees
`@galaxy` and the pack's own modules (`./name`) under `scripts/`, plus `lib/` if
the manifest sets `lib = true` (never `tests/`). Sandbox and snapshots are CLI
only (`galaxy gm`, `galaxy sim`).

## Sandbox rules

- **No memory between calls.** Each handler call, beat callback and `G.test`
predicate runs the script and its modules afresh in a fresh Luau state, so
module-level locals start over every call. What a script must remember goes in
its declared `stores` (saved with the world).
- **One cause per call.** A second `ctx:cause` is an error. The call's writes are
one batch: if any would be rejected, none apply.
- **Faults and contention.** Only script faults count as aborts toward
`limits.quarantine_after`: an error, running over the step, memory or write
quota, an invalid argument, an undeclared hook, or a write that would be
rejected on the world the call read. A write that is valid there but loses to
a change made earlier in the tick (the ship undocked, cargo moved, a
compare-and-set or `Expect*` check failed) is contention and never counts. A
beat transition or `after.` trigger simply tries again next tick. An `on.`
handler runs again for the same event next tick, up to
`limits.contention_retries` times (default 3); if it still loses it is dropped
with a `script_contention_dropped` fact. The retry reads the world as it is
then, so check what you rely on (`ctx.beats:pilot().docked_at`) rather than
letting a hook raise.
- **Deterministic.** `tostring` and `string.format` print tables, functions and
buffers as their type name, never an address. `pairs` and `next` refuse tables
keyed by tables, functions or buffers (their order isn't stable). A generic
`for` names exactly one `pairs(...)`, `ipairs(...)`, `string.gmatch(...)` or
`utf8.codes(...)` call, or `next, t`, between `in` and `do` (or a local that
only aliases one of them): anything else, such as `for k, v in t` or
`pairs(a) and t`, is a check error. The garbage collector doesn't run during a
call, so weak tables don't change under a handler.
- **Limits.** Per call: `limits.steps_per_call` steps, `limits.memory_bytes` of
Luau memory (everything the call allocates, garbage included), and at most
256 writes holding 256 KiB. Library functions that do work in proportion to
their input (`pairs`, `next`, `table.sort`, `string.rep`, `string.find`, history
queries ...) charge steps for it: one per table slot or element, one per 64
bytes. Text that leaves the call (error messages, `print`) is cut to 1 KiB,
and a recorded fact's note is at most 1 KiB.
Arguments to `ctx` are size-checked before they are
copied. Numbers passed to `ctx` must be whole where a whole number is expected
and in range; nothing is truncated or wrapped.
- **Strict types.** Every file a script can load is typechecked in strict mode.
Its first line must be `--!strict`, and `!nocheck` or `!nonstrict` anywhere in
it, even in a comment or string, is a check error.
