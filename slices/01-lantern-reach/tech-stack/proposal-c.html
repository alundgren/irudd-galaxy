Lantern Reach — tech stack, proposal C

The slice runs as a custom engine: a Rust simulation that changes only with a release, a sandboxed Luau layer where the game master works live, and an optional local model that never sits on the frame. It targets this PC — Windows 11, RTX 5070 Ti (16 GB), i5-14400F, 32 GB RAM — and it plays with the network off. The code stays inside slices/01-lantern-reach/ until a later release promotes it to game/.

Read first, and treated here as source of truth: the Lantern Reach slice (20 systems, 14 hooks, 7 shared interfaces, 8 live change types), the high-level plan, and the fast-model research. This proposal answers the slice's open stack question in favor of a first cut of the custom engine, so the line between the two layers is real code.

One line per layer

Recommendation Rust sim, Luau scripts, llama.cpp beside it.

The base engine owns the step, the verbs, the price formula, saves, and the hook table. Luau revisions turn those hooks on, write world facts, and hot-reload at a dock or a pause. Utility AI keeps traders moving with the model deleted. One CLI is the game master's only door.

Layer Recommendation

Base engine

The base is the part a release replaces. It is a library plus a thin host. The slice's twenty systems live here when they are rules, and in data or scripts when they are content. Rendering is a sprite batch on purpose: the experiment is the line between the layers, and a sketched top-down game needs one shader.

Step, world, pause

The host polls input into a plain struct and calls sim::step at 60 Hz while the game is running. A hitch drops steps. The world slows on screen and does not lurch forward to catch up. The harness calls step in a loop with no window, and that loop is the only fast-forward. Pause sets a flag the host already has: step is not called, looping sounds stop, and the pause card from Proto 6 stays up. Apply and rollback are legal while that card is up, and while the ship is docked.

World is a struct of tables keyed by stable ids (station:kettle-dock, fact:41). Ids are monotonic integers minted by the base and stored in the save. They survive reload and are never reused. Iteration uses ordered maps so two clones with the same seed and the same inputs hash the same. Each system (market, rocks, utility tie-break) has its own SplitMix64 stream in the save. The sim crate has no thread, no system clock, and no HashMap in world state. A canonical hash of two forks is a test.

After each step the sim returns a queue of events. It does not call scripts itself. The script crate drains the queue, runs handlers, and pushes a command buffer. The sim applies that buffer before the next step and does not re-enter step from a handler. A script reaction is visible on the following step. Validation uses that same loop, so the delay in play is the delay in the report.

What the base implements

These behaviors ship in the binary. Scripts can turn them on, parameterize them, and record facts. They cannot replace the functions.

  • Flight integration for arcade WASD that zeroes on key-up, plus the reserved control tiers (click to fly, click to mine, click to dock, map click, queues, loops). A tier stays dark until a mechanic flag is enabled.
  • The order executor for fly, mine, dock, buy, sell, wait, and loop, shared by the player ship, the automated craft, and scripted NPC craft.
  • Mining: three rock types, visible depletion, persistence, regrowth driven by activity counters.
  • Docking rings, holds, the six commodities, hullwright and dockmaster services.
  • The price function: producers, consumers, saturation, recovery by activity. Scouted prices are snapshots dated by the last visit.
  • Faction standing as stored memory of deeds. How a person treats you is content. The storage is base.
  • Pilot traits as a small set of qualitative modifiers the sim already understands, and the prestige rule that the world persists while hull ranks reset for a fee.
  • Activity counters per player, station, and region (dockings, deliveries, jumps, sessions). No clock is readable from script.
  • Save, clone, history, the hook dispatcher, the validator, and the revision stack.

Save

The running game is the in-memory World. A save is a directory:

saves/<id>/
  world.json        current world, stable ids
  history.jsonl     append-only facts
  revisions.json    applied revision ids, newest last
  snapshots/        one pre-image per live revision

History is a log. The world is a snapshot. Rollback restores a pre-image and appends a fact; it does not delete lines from the log. Queries that drive the sim read the world. Queries the game master makes can see superseded facts. Rebuilding the world by replaying history is a bug, and a test loads a save that contains a rolled-back revision and checks the world matches the pre-image.

The CLI prints the same JSON it stores. Agents read files. They do not scrape a window. A later sync layer can replace the directory with SQLite behind a SaveStore trait. The sim never opens a database during step.

Presentation

W6 owns host. One textured-quad pipeline draws hulls, rocks, stations, and UI from the asset kit, addressed by id. Stations are assemblies of kit parts and a stage id, which is how Kettle Dock grows and how the sixth station is born without a new mesh format. Input is an Input frame. The sim never calls the OS. Audio is kira, and none of the rejected mining-beam or engine loops are imported. Silence plus a few new clips is a valid slice; the host just has a clock that pauses.

The host starts as colored quads. Art arrives at the last gate. The sim, the bot, and the script jail do not wait on shaders. wgpu is there so a later Mac or Linux build does not grow a second renderer. The slice itself ships a Windows launcher only.

What a release is

A release is a new native binary. It is required for a new order-verb implementation, a new price formula, a new hook, a new trait modifier the sim cannot already express, a flight-model change, a save migration that is more than adding a field, and any change to the renderer or the audio device. Hot-swapping that binary is out. The player restarts.

Scripting layer

The game master writes a revision: a JSON manifest plus a Luau file. The CLI validates it. At a calm moment the host applies it. The authored backbone under content/ already plays the journey, so a rejected revision leaves a complete game.

Why Luau

Luau is the live language because untrusted game scripts are what it is for, and because agents already write Lua. mlua's luau feature embeds the official language, and Lua::sandbox locks the state down. --!strict plus a galaxy.d.luau definition file checks calls against the hook list. The script crate is the one place the workspace needs a C++ toolchain, to compile Luau. sim builds without it.

Rhai would keep the whole workspace in Rust and has real operation limits. It loses because the live layer is the language written every session, and Luau is the one the game master and the coding agents already produce. Wasmtime is the stronger jail and the wrong edit loop: a live change would be a compile. It stays a later option if a revision ever comes from outside this one operator. A pure-Rust Luau VM is too new to bet the slice on.

Two entry points

on_apply runs once, in the sandbox fork and then on the real world. Its writes are facts. They persist in the save. on_load runs whenever the revision is active: after apply, and after every load. It may register handlers, beats, and fast-model briefs. The validator rejects a world write inside on_load, which is what stops a shortage from being applied a second time when the save opens.

A revision that replaces another must roll the old one back in the same calm moment. The past facts stay in the log, marked superseded. There is no silent merge of two live writers.

Sandbox

Jail The script sees galaxy and a pure standard library.

  • 1 Fresh Luau state per revision. Lua::sandbox. Libraries present: math, string, table. Absent: io, os, debug, package, and any file or network loader.
  • 2 An instruction interrupt. on_apply has a budget for the load. Each event handler has a tighter one. Over budget during validation rejects the revision. Over budget during play logs the failure and skips that handler. The sim keeps stepping.
  • 3 Values that cross the boundary are ids, numbers, strings, and plain tables. No userdata pointing into World. Handlers cannot hold the world across a step.
  • 4 Every write is tagged with the revision id by the host. The script does not supply its own cause string.

Hot reload, three tiers

Tier What moves When it lands
Kit and content files Sprites, stage lists, authored JSON When the file parses. A bad file keeps the last good sprite or table, as Proto 6 did.
Script revision Manifest plus Luau After the six gates, at a dock or a pause. Old handlers unregister, then on_apply and on_load run.
Native binary Sim, host, validator, verb code A release. The process restarts. No hot swap.

Validation

Every revision, including the eight live changes and the one deliberate reject, walks the same gates. The report is JSON. A failed gate stops the walk.

  1. 1
    Schema and types

    The manifest matches script-manifest.schema.json. The hook list is a subset of the fourteen. Luau parses, --!strict passes against galaxy.d.luau, and a host walk rejects any call outside galaxy.*.

  2. 2
    Canon

    Cited nodes exist in the small Ancients graph. Terms reserved by uncited nodes fail the gate. Chapter one at Glass Drift can open. A later chapter cannot sneak in.

  3. 3
    Invariants

    A shock names an opportunity. The manifest names a place and a person that exist. Static bans cover timers, level-scaling fields, and destruction of player property. The dynamic half of this gate runs after the sandbox.

  4. 4
    Sandbox run

    Clone the world, run on_apply and on_load, then fast-forward headless on utility AI with the model off. Prices stay inside the bands telemetry already records. The bot can still reach the next authored beat. Player property ids are still present.

  5. 5
    Legibility

    Every lines.post in that run carried a fact id that existed at post time, and a place and a person. A change nobody could meet fails here.

  6. 6
    Calm apply

    The host is docked or paused. The pre-image is stored, then on_apply runs on the real world. Mid-flight, the revision stays proposed and the CLI exits with a distinct status. The report says which gate failed.

{
  "revision": "sha256:…",
  "ok": false,
  "gates": [
    {"name": "schema", "ok": true},
    {"name": "canon", "ok": true},
    {"name": "invariants", "ok": false, "detail": "shock has no opportunity"}
  ]
}

Rollback

Rollback is an in-world act, not a file revert. At a calm moment the host restores that revision's pre-image, unregisters its handlers, appends a revision_rolled_back fact, and posts a chronicle line that cites it. The script file stays on disk so the agent can read the report and propose again. History keeps the failed attempt. The world no longer shows it. The stack pops one revision at a time, newest first, and the pre-images live in the save so a reload does not forget them.

The eight slice changes all fit on the script side: station growth, a shortage, territory, a rumor, enabling a reserved verb with a teacher, Ancients chapter one, the sixth station assembled from the kit, and the chronicle.

The call list

Scripts call this and nothing else. Writes return a fact id minted by the host. Reads return plain tables.

Hook Script call Rights
Event hooks galaxy.events.on(name, fn) Subscribe. Names: dock, undock, mine, rock_depleted, buy, sell, scout, order_done, quest_step, trait_earned, prestige. Payload is ids.
Activity counters galaxy.counters.get(scope, id, name) Read.
World stores get, patch, create Typed read and write. create takes a type id that already exists in the catalog or the kit.
Player history galaxy.history.query(filter) Read. Append happens inside every write.
Canon graph galaxy.canon.cite(node) Read. Citing a missing node fails the revision.
Market levers scale_producer, scale_consumer, add_stock Write. The price formula stays native.
Mechanic registry galaxy.mechanics.enable(flag) Write a per-save flag the base already reserved. An unknown flag fails validation.
Order verbs galaxy.orders.issue(actor, verb, args) Issue a verb the executor already implements.
Asset kit galaxy.kit.set_stage(id, stage, variant) Write. Parts come from the kit manifest.
Beat API beats.register, beats.mark Register preconditions and an end state. Mark progress with a fact id.
Legibility galaxy.lines.post(channel, line) Write a dock line, map note, or chronicle entry. text, fact, place, and person are required.
Fast-model budget fast.set_budget, fast.set_brief Write menus, bands, and a per-region call budget. The model is not invoked from Lua.
Sandbox and snapshots Host only Fork, fast-forward, compare, restore. Scripts cannot call these.
Telemetry Host and CLI only lantern gm metrics reads economy and activity per region. The sandbox gate reads the same numbers.

A revision, the short form

Ice shortage, one of the eight. The manifest carries the shock, the opportunity, and where a person will say it. The host sets g.fact to the fact id for this apply. The script only calls hooks. The beat id is registered by the revision, and the end state is one the authored backbone can already complete.

{
  "id": "shortage-ice-shallows",
  "cause": "Heavy ice mining in the Shallows",
  "place_id": "station:kettle-dock",
  "person_id": "npc:dockmaster",
  "shock": "Ice runs short at three stations",
  "opportunity": "Bring ice, or sell rations to the greenhouse",
  "canon": [],
  "hooks": ["market", "lines", "events", "beats"]
}
--!strict
function on_apply(g)
  g.market.scale_producer("station:shallows-field", "ice", 0.4)
  g.lines.post("chronicle", {
    text = "The ice field is thin. Kettle Dock will pay for a load.",
    fact = g.fact,
    place = "station:kettle-dock",
    person = "npc:dockmaster",
  })
end

function on_load(g)
  g.beats.register({
    id = "shortage-ice",
    when = { event = "rock_depleted", commodity = "ice" },
    end_state = "ice delivered to kettle dock",
  })
  g.events.on("rock_depleted", function(e)
    if e.commodity == "ice" then
      g.beats.mark("shortage-ice", e.fact)
    end
  end)
end

Seven contracts

W1 owns these files. Other workstreams change them by a contract edit, not by reaching past them. Each schema has fixtures. A Rust test loads the fixtures and rejects a sample that drifts. No code generator sits in the middle.

  • world-state.schema.json — stable ids for stations, rocks, ships, NPCs, factions, facts.
  • events.schema.json — event names, payloads, and the activity counters.
  • order-verb.schema.json — the shared verb set and its arguments.
  • galaxy.d.luau plus the hook table above — the only surface scripts can reach.
  • script-manifest.schema.json and validation-report.schema.json — proposal in, report out, invariants included.
  • asset-manifest.schema.json — sprite slots, station stages, variants, by id.
  • text-channel.schema.json — every line cites a history fact.

Fast-model layer

The fast layer is a client behind a Rust trait, not a library inside Luau. The game master sets briefs and budgets through galaxy.fast. The sim decides when a decision exists. The frame never waits on a model.

  1. Script sets the brief

    Goals, temperament, allowed actions, limits, knowledge, voice, and what is off limits. A call budget per region.

  2. ↓ stored on the NPC or the region
  3. Something happens near the player

    A dock, a jump, a ship you can see. Background craft stay on utility AI. There is no per-tick poll.

  4. ↓
  5. Utility AI scores the menu

    Deterministic given the world. This result is already legal. Routes and cargo commit it on this step if no model answer is already waiting.

  6. ↓ batch at the quiet moment
  7. Sidecar, if it is on and inside budget

    llama-server, CUDA build, Qwen3.5-4B at Q4_K_M. The request is a grounding packet and a JSON schema. The answer is an action id from the menu, plus a short line only when the channel is talk.

  8. ↓
  9. Six checks, then the world

    Shape, ids from the packet, preconditions, the brief's bands, text length and banned canon terms. A failure keeps the utility choice and an authored line. No retry loop.

  10. ↓
  11. History

    The outcome is a fact. The game master reads it later with lantern gm history. Dock talk stays silent when no line passed. Silence is the authored behavior.

The research's starting setup is the one this slice uses. Utility AI is the base, so the game is complete with the sidecar absent. The local model is Qwen3.5-4B at Q4_K_M, Apache-2.0, with weights the research estimates near 3 GB, inside a 4–6 GB VRAM budget that leaves the card to the game. The runtime is llama-server, shipped as a sidecar the host starts on a free port and stops on exit. Players install nothing. Gemma 4 E4B is the alternate weight if a measured run says Qwen is the wrong small model. OpenRouter, including a cheap structured model or TypeSafe Jev for typed choices, is a third implementation of the same trait and defaults to off. The slice's offline pass is the utility path.

World-affecting choices do not upgrade late. If the model answer is not ready when the step commits, utility stands, which avoids a route that flickers. Dock lines can wait until the next calm moment and then say nothing if the check failed. The same NPC, the same facts, and the same menu reuse a cached answer. A regional budget the script set, once spent, leaves utility in charge for the rest of that activity period.

The 2D host should be a small neighbor on a 16 GB card. That is a hope until prototype 3 measures frame time with the sidecar resident and with it killed. The sim thread never calls the server. A dead sidecar is the toggle switching off.

Why agents can work here

Most of the code will be written by agents. The stack gives them a closed door for each kind of change, and a command that tells them they are wrong.

CLI One binary, three jobs.

lantern play
lantern gm state --json
lantern gm history --since fact:40 --json
lantern gm propose scripts/shortage-ice/
lantern gm apply sha256:…
lantern gm rollback sha256:…
lantern gm metrics --region cinder --json
lantern harness bot --from beat-1 --to beat-17
lantern harness jump beat-9

Propose prints the validation report and does not apply. Apply refuses unless the session is docked or paused. There is no second integration for a named coding assistant. A later MCP wrapper can shell out to this CLI.

Tests and the headless sim

cargo test -p sim needs no window, no GPU, and no Luau. It covers the pause (zero steps), the save round-trip (same ids), and two forks (same canonical hash). cargo test -p script runs the good examples and the bad fixture: a timer, a missing fact, a canon slip, a destroyed hold, a shock with no opportunity, an unknown hook, a write inside on_load. lantern harness bot is the shared journey test from the slice, run against the authored backbone with the fast model off. Jump-to-beat saves let an agent land on act 3 without playing act 1 by hand. The debug overlay is a host flag for Andreas. Agents use the JSON.

The sim API takes ids and plain structs and returns the same. No lifetimes cross a crate boundary. Agents that fight the borrow checker are almost always reaching into World from the wrong crate, and the fix is a command, not unsafe. sim forbids unsafe. Script FFI stays inside the script crate.

Two stacks that lost

Both would ship a window sooner. Both leave the engine line soft, which is the question this slice is here to answer.

Lost Godot 4, C# for systems, GDScript for the live layer

Godot already has a headless mode, a desktop export, and live script reload. It is the right place to judge flight feel if the custom engine were not the point. It loses here because the release-only side would be Godot itself. A GDScript revision can reach the scene tree, the filesystem, and nodes that were never in the fourteen hooks. Cloning a scene for a sandbox fork keeps signals and hidden state, so rollback cannot mean "restore this struct." The slice would finish without ever drawing the line it is supposed to prove.

Lost C# and MonoGame for the base, NLua for scripts

This is the serious rival. Agents write C# fluently, dotnet test is a fine headless loop, and MonoGame is a honest sprite host. It loses because the base and the scripts share a runtime. The path of least resistance for a new verb is a new managed assembly, which is the DLL-shaped mod the plan rules out. Rollback then has to unwind delegates and events, not restore a value. Lua under NLua can be fenced, and the fence will not hold once both sides are one GC heap and one debugger. Rust makes the illegal reach annoying in the compiler, which is the property the agent loop needs on the base. C# would win if the goal were the fastest first playable and the engine line could stay a document.

The web stack in the high-level plan (Tauri or a page) stays out for the reason already written there: flight, pause, and a game that is lived in sit poorly in a webview, and a JavaScript game master inside a JavaScript game has no separate jail. The HTML toys were already rejected as presentations.

Risks and three prototypes

The order is the de-risking order. Prototype 1 is playable with the script crate absent. If the jail fails, the hands-on ship can still be judged, which keeps the engine experiment parallel to the game as the plan requires.

Risk What it looks like What holds it
Borrow-checker churn Agents spend their turns on lifetimes in the base and avoid the game. Ids and command buffers cross crates. sim forbids unsafe. Daily game-master edits are Luau, which does not have lifetimes.
Types mistaken for proof --!strict is green and the economy still runs away. The sandbox fast-forward and the price bands are the gate. The typecheck is only gate 1.
Flaky forks A HashMap or a clock read makes two sandboxes disagree, and someone disables the test. Ordered maps, per-system RNG, no clock in sim. The hash test is part of prototype 1.
Double-apply on load A shortage script runs again when the save opens and the field collapses twice. on_load cannot write. A test loads the same save twice and compares hashes.
GPU fight llama-server and the frame stall each other on the 5070 Ti. Prototype 3 measures both. The sim never awaits the server. Killing the sidecar leaves utility AI.
Contract drift Six workstreams invent a fifteenth hook in a system file. Fixtures plus the allowlist. A new hook is a W1 contract change and a release.
C++ toolchain Luau fails to compile on a machine that only has rustup. The C++ dependency is confined to the script crate. Prototype 1 links nothing but Rust.
Rollback that lies Numbers return and the station art does not, or the chronicle pretends it never happened. The pre-image includes kit stage. Rollback appends a fact and posts a line.
  1. 1
    Headless Wren loop

    Fixed step, real pause, one ship, one rock, dock, sell, save, load. Stable ids. Two forks of one seed match. A Rust bot flies it. A window is optional and can be colored quads. No Luau yet. This is the hands-on ship the prototypes asked for, and it is the deterministic core the later gates sit on.

  2. 2
    Script jail

    One revision adds stock at Kettle Dock when ice is delivered. One bad revision is rejected with a report. A second revision hot-reloads at pause without a native rebuild. Rollback restores the market hash and leaves a chronicle line. This is the engine line in miniature.

  3. 3
    Fast sidecar

    Utility AI picks a trader route. With the sidecar up, Qwen3.5-4B returns a schema-constrained pick while a sprite keeps moving. Kill llama-server and the route still resolves. Record frame time with the model resident and with it gone, on this PC, before any later weight is considered.
