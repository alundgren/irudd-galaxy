IRUDD GALAXY / LANTERN REACH / PROPOSAL B · 29 OCTOBER 2026

A native core.
Live, typed world logic.

Base engine: C++20 + SDL3, with a custom deterministic simulation and SQLite saves, shipped as a Windows native release.

Scripting layer: strict Luau in a restricted worker, delivering versioned logic, data and asset packages through validated transactions.

Keep the experiment in the simulation, tools and live world. Use libraries for windows, sprites, sound, persistence and the language VM. The decisive test: grow a station, change a shortage rule and add rock tagging during play without rebuilding the executable or losing anything the player earned.

Target: Windows 11 · RTX 5070 Ti, 16 GB VRAM · i5-14400F · 32 GB RAM. This is an architecture proposal, not a tested engine or a hardware benchmark. Scope and API names below are proposed.

1. Own the simulation; keep the renderer small

The game is a calm 2D trader. It needs warm illustrated sprites, readable routes and durable consequences. It does not yet need a general editor, a 3D renderer, rigid-body physics or a universal entity framework.

PieceChoice and responsibility
Native foundationC++20, MSVC x64, CMake presets + Ninja. Explicit value types, RAII, bounded containers at external boundaries and stable handles instead of cross-system raw pointers. Pin compiler and dependency revisions; no native hot reload.
Window, drawing, input, soundSDL3 with its 2D renderer, selecting Direct3D 11 on this PC. SDL_image for PNG and SDL_ttf for bundled fonts. Atlas sprites, tinting, layered station parts and a small native UI. SDL audio for a fresh, quiet sound pass. SDL offers accelerated 2D primitives and selectable drivers [1].
SimulationA standalone galaxy_sim library, with no SDL, GPU, network or model dependency. Fixed 60 Hz movement; integer quantities and currency; fixed-point positions; explicit seeded random streams and stable iteration order. Typed stores for the small slice rather than a custom generic ECS.
Rules and pacingNative order executor, cargo ledger, market formula, docking, depletion, activity counters and invariants. Scripted policies choose conditions, offers, bounded modifiers, goals and consequences. Market recovery, regrowth and unlocks advance from activity, never elapsed real time. wait means waiting for a condition, not a countdown.
PersistenceSQLite C API: one local save database, one engine writer, rollback-journal mode with full synchronization. Store checkpoints, committed commands, append-only facts, package versions, script state, random seeds and decision results together. Use transactions and the backup API for consistent forks [2].
Contracts and diagnosticsJSON Schema for wire formats; nlohmann/json plus a pinned schema validator. Generate matching C++ DTOs and Luau definitions for the supported schema subset. Catch2 + CTest for local tests; Dear ImGui only for the developer overlay, never the visual identity of the game.
DistributionOne launcher with the native executables, pinned runtime libraries, authored content, fonts and license notices. Optional model pack installed separately. No Python, Node, editor, account, network or model download needed to play. Build dependencies are cached for repeatable local builds.

Pause is a simulation barrier. P or Escape stops movement, orders, markets, NPC decisions and activity. The obvious PAUSED overlay stays visible. Background validation may finish; approved package installation may occur at that barrier without advancing the world. Model responses cannot mutate the paused world.

Save compatibility is explicit. Stable opaque IDs survive reloads and never get recycled. A save names the engine schema, API major version, exact content hashes and pinned Luau revision. Retain every package and asset referenced by a retained save. Migrate a copy on an engine upgrade; preserve the original and reject newer unknown formats. Promise replay for the same pinned build, not bit-identical behavior across arbitrary compilers or future releases.

The target is Windows first. Keep SDL and platform code outside the simulation so later Mac/Linux work remains plausible; this proposal does not add packaging for them. The slice stays self-contained, and game/ must never depend on slices/.

2. Reload packages, not native code

Luau supplies a Lua-derived scripting language with a gradual type system and strict checking [3]. Require --!strict, generated host definitions and zero type errors. Scripts can express new event-driven algorithms and compose mechanics, not merely fill predefined event cards. Static types help agents; the native validator remains authoritative.

  1. Game masterReads facts; proposes source, data, assets and a manifest.
  2. →
  3. Luau workerReads frozen input; returns new script state and typed commands.
  4. →
  5. Native validatorChecks the whole transaction; commits it or changes nothing.

Only the native engine owns world state, durable history and save files.

Sandboxing is an embedding responsibility

Run the compiler, analyzer and VM in a separate native galaxy-script-host.exe. Use a Windows AppContainer with no network capabilities or access to player saves, and a Job Object with memory/process limits and kill-on-close. Transfer bounded messages through explicitly permitted IPC handles. Restrict access to the worker's own runtime files and scratch area. Prove that launch and IPC arrangement in prototype 1; a separate process alone is not a security boundary [4].

Inside each package VM, freeze libraries and globals with Luau's sandbox helpers. Expose immutable snapshots and command constructors only. Remove clocks, filesystem loaders, environment access, unrestricted require, debug facilities and random sources; permit only manifest-listed internal modules and a host-seeded random API. Accept source only and compile it with the bundled compiler: Luau does not promise safety for arbitrary input bytecode [5].

Proposed starting limits: 1 MiB source per package, 32 MiB Luau allocations per VM, 256 MiB worker process, 256 commands per event batch and bounded query/string/collection sizes. Count VM interrupt callbacks deterministically, cap host-call work, and use an external watchdog as the emergency stop. These are limits to tune, not measured capacity. Compilation and asset decoding get limits too. A killed or over-budget worker yields no commands; the native world keeps running. Luau's interrupts and allocator controls need host enforcement [5].

One package, one recoverable transition

A package contains manifest.json, Luau source, schema-checked data, optional bounded PNG assets, fixtures and a state migration. The manifest declares package/revision IDs, engine API range, predecessor hash, capabilities, state schema, cause fact IDs, affected IDs, person/place of notice and compensation policy. Custom script state is serializable, size-limited and namespaced; closures, VM heaps and native addresses never enter saves. Packages cannot load Python or DLLs, replace host functions or inject native code.

  1. Stage immutable bytes. Hash a complete package, reject unknown fields, unsafe paths, undeclared imports and assets beyond size/pixel limits. A watcher or CLI stages a candidate; partially written files cannot go live. Publish and flush package/asset bytes before committing any save references to them.
  2. Check types, references and authority. Analyze source; verify IDs, capability grants, canon prerequisites and schema migrations. The manifest requests capabilities; it cannot grant them to itself. Content cannot replace native validators.
  3. Prove consequences on a fork. Run the exact candidate against the current save and deterministic action fixtures: help each way, ignore, repeat, save/reload and rollback. Check reachable goals, affordable escape paths, bounded prices, conservation, no lost property and a real opportunity for every shock. Clock-driven conditions and level/wealth-scaled threats have no approved API. Script analysis alone cannot prove their absence; review command traces and adversarial scenarios too.
  4. Validate legibility. Require a cause, a named place and person, an observable world change and history-backed text. Locked Ancients facts cannot be authored or contradicted by a package. Only prerequisite-checked chapter reveals are permitted; new canon needs a reviewed release.
  5. Install at a calm barrier. Docked or deliberately paused, drain pending command batches, snapshot, recheck the save revision and validate the migration. If the world changed since the fork, rerun affected checks or reject as stale. Commit active package hashes, state migration, effects and history in one SQLite transaction, then publish the new in-memory state. A restart reconstructs that committed state.
  6. Keep the last good version. Fresh VM, fresh subscriptions, migrated explicit state; remove old subscriptions atomically. Event IDs and cursors prevent duplicate rewards. Runtime outputs still pass validation. On failure quarantine the package, discard the full batch and route its hooks to the compatible last-good package or authored fallback. Test the reverse state adapter too; if it cannot preserve current progress, retain an engine-owned compatibility handler instead of restoring stale script state.

Rollback has two meanings. Before the player resumes, restore the pre-apply checkpoint and package set exactly. After play has continued, use engine-owned compensating commands: remove a shortage modifier, retire its offers, preserve purchased cargo, retain deliveries and append correction facts. Never rewind credits, discoveries or prestige earned since installation.

Every mutating capability must have a defined compensator. A spawned station becomes a dormant, accessible landmark if players used it; occupied docks and cargo cannot vanish. Mechanics already used retain a compatibility handler for outstanding orders. Never “unlearn” a revealed Ancients fact. Packages that cannot safely retire their effects fail validation before application. If compensation itself fails, disable further package effects and preserve the save for recovery; do not silently restore an old world over progress.

3. A small API with enough room for all eight changes

Release-only: scheduling, physics and order primitives, price calculation, persistence, resource ownership, capability checks, canon locks, asset decoders, renderer, input/UI slots and the interpreter. Live: event logic, progression predicates, bounded economy policies, faction behavior, NPC briefs, rumor propagation rules, station assemblies, validated textures and composite mechanics.

At an event boundary, the engine batches subscribed events and a bounded read projection for the worker. It receives {baseRevision, eventCursor, nextState, commands[]}. The engine checks preconditions again and applies the batch atomically in stable order. Worker latency never blocks flight. Effects enter only at a simulation barrier; replay records that barrier and the accepted commands. Package installation waits for dock/pause; ordinary installed-script reactions run at event barriers during play.

A new verb means a new composition. Rock tagging can combine an existing target selector, a metadata tag, map marker, reserved action slot and teacher demonstration. New behavior may branch on history and use the seven order primitives. A new physics primitive, arbitrary shader, native module, raw UI widget or unrestricted input binding needs a release. Do not advertise unrestricted runtime invention.

The seven interfaces to freeze first

  1. World schema: IDs, revisions, units, ownership, extension namespaces and save migration rules.
  2. Events and counters: payloads, ordering, subscriptions, cursors and what increments each counter.
  3. Orders: tagged union of the seven verbs, preconditions, cancellation and completion results.
  4. Hooks: the 14 surfaces above, capability grants, command schemas, limits and compensators.
  5. Script manifest and validation report: versioning, hashes, migrations, cause/notice metadata and machine-readable diagnostics.
  6. Asset manifest: sprite slots, parts, stages, anchors, texture hashes and budgets.
  7. Text channels: speaker/place IDs, fact references, template fields, visibility and correction links.

The authored package can carry every one of the 17 journey beats with the game master absent. It ships examples of all eight change types as well. Independent live proposals enrich that backbone; they never become a prerequisite for completing the slice.

4. A model can improve a decision; it never holds up play

Start with utility scoring for traders, dock talk and rumor spread. Then test the research document's candidate, Qwen3.5-4B Q4_K_M via a native CUDA llama.cpp sidecar. Treat model identity, quantization, license and target-driver support as packaging checks, not assumptions that this proposal has benchmarked. Keep OpenRouter out of the initial slice; the adapter leaves room for a later explicit opt-in.

The broker sends {requestId, saveRevision, npcId, briefHash, factIds, allowedChoices, budget}. The response is {requestId, choiceId, factIds}, plus an optional short utterance candidate. llama-server supports constrained JSON output, loopback binding and API authentication [6]. The broker still validates IDs, current preconditions, faction permissions, amounts and budgets; valid JSON is not a valid game decision.

  1. Compute the utility answer immediately. Only near-player, event-triggered requests may enter a bounded queue. Start with one inference slot, a short context cap and capped output; no model calls per simulation tick.
  2. Use a cached valid result if available. Otherwise prefetch for a later action boundary. If the decision is needed now, execute the utility choice once. Never apply a late model response over an already executed fallback.
  3. Key the cache by relevant state, choice set, NPC brief and model revisions. Discard stale answers. Commit the selected result, reason, facts and event barrier to history; replay uses that record without rerunning inference.
  4. On pause, hold or discard outstanding results. On missing weights, crash, invalid output, overload or disabled inference, continue with utility AI and authored text. The broker starts and stops only its own sidecar, on loopback with a per-launch credential.

Facts are stricter than prose. A fact ID next to a sentence does not prove that sentence true. In this slice, let the model select fact-backed authored lines; optional phrasing is limited to approved templates and slot values. Ancients text stays authored. Later free-text experiments need their own acceptance tests. Preserve rumor truth metadata even when the speaker is lying.

The game master authors briefs and policies asynchronously; it never pilots NPC ships. The fast layer chooses among legal options, and ordinary native orders do the work.

Use the same galaxy_sim in the client, CLI, validation forks and tests. The headless mode substitutes only input and presentation, not economy or progression. Most work can be verified from a saved state and a command trace without launching a window.

Offline validation works on a copy. propose queues validated content for automatic installation at dock/pause, not a player approval inbox. Return JSON diagnostics with stable codes, source spans, failed invariants, state diffs and replay commands. Verification is local. Test ledger invariants, generated schema round trips, replay, migration, fault injection at each commit phase and the full journey. Fuzz package parsers and worker messages; use AddressSanitizer builds for the C++ boundary. Keep screenshot checks for layout and art separate from simulation tests. No routine CI workflows or GitHub Actions jobs; Actions are reserved for release creation/publication.

The bot can prove reachability and consistency, not delight. Preserve the design gates: Acts 1–2 with a script applied and rolled back, then the entire journey with all eight live changes, then Andreas playing the art/audio pass. Compressed activity thresholds are a slice setting, not a change to the full game's long progression.

6. Two alternatives, and why they lose here

StackWhat it winsWhy not choose it
Rust + winit/wgpu + RhaiA native custom engine with Rust memory safety, Cargo tooling and controllable scripting limits. wgpu supports native GPU backends; Rhai documents resource controls [7].Strong runner-up. For this sprite-scale experiment, explicit GPU pipelines and a Rust/script binding layer add work we do not need to answer the live-world question. I prefer SDL's ready 2D drawing and Luau's strict authoring surface. Reconsider if C++ boundary defects dominate the first prototype.
Godot 4 + GDScriptAn integrated 2D engine, editor and desktop export pipeline [8]; likely the lower-infrastructure route if the goal were only the game.Fails the explicit experiment in building a custom engine. General scene scripting also is not this capability-restricted GM boundary; a separate proposal validator remains necessary. Choose only if Andreas changes that objective.

The recommendation accepts C++ ownership and build complexity in exchange for direct native integration with SDL, Luau and SQLite. It deliberately postpones custom shaders, a general ECS, an editor and a second scripting language. These are design judgments, not measured comparisons of agent productivity.

7. Risks, then the first three prototypes

RiskResponse and failure signal
Unsafe native boundarySmall DTO-only IPC, no pointers to script, sandboxed workers, fuzzing and sanitizers. A worker that can access saves/network or crash the client blocks live-agent use.
Rollback removes progressEngine-owned compensation and retained compatibility handlers. If a used station, cargo, revealed fact or earned hull disappears, that capability is not ready.
Finite tests miss harmful logicNative command restrictions, runtime invariant checks, diverse trace fixtures and package quarantine. Sandbox success is evidence, not proof; wealth scaling and dead ends need explicit adversarial cases.
Interpreter / IPC too expensiveBatch event projections; no per-frame script polling. If flight waits for a worker, the boundary is wrong. Move hot primitives into a release rather than widening privileges.
GPU contention or weak model outputMeasure paired game/model load; cap or disable inference. Keep meaningful routes and authored factual lines available with rules alone.
Art or content still feels genericTeach one real mechanic, recur with named people and show physical consequences. A technically valid change that Andreas cannot notice fails the slice's design test.
  1. Prototype 1 — break the live boundary. One saved station, a delivery event and two Luau package revisions. Reload growth logic while docked; migrate state; restart at each persistence phase; compensate after a purchase. Inject an infinite loop, allocation storm, forbidden import, fake fact, malformed asset, stale revision and duplicate event. Pass only when failures leave the world intact, the worker cannot reach saves/network, and the prior behavior survives restart.
  2. Prototype 2 — fly the deterministic backbone. Wren, two docks, three rock types, a saturating market and activity-based control unlocks. Exercise queues, a distinct automated task and one prestige transaction through the same executor. Compare client and headless replay hashes, pause during each operation, and visually judge stop-on-release flight and mining. Pass only when the loop feels right, save/reload preserves the world, and the API can teach rock tagging without a native rebuild.
  3. Prototype 3 — combine live world and optional inference. Expand the harness to three regions, the eight change packages and a novel sixth-station assembly. Run the full journey on the target PC with no model, then with the candidate local model under render load. Record p50/p95/p99 frame times, peak RAM/VRAM, decision latency, stale-result rate and fallback frequency. Proposed acceptance target: p95 frames at or below 16.7 ms at 1080p, no gameplay wait for inference, complete offline journey, preserved progress after compensation, and at least one history-caused change Andreas notices unaided. If inference spoils play, ship the same slice with it off.

These are proofs ordered by architectural risk, with no development time estimates. The first prototype is the stop gate for the engine boundary; the third tests the recommendation under the actual hardware and content load.
